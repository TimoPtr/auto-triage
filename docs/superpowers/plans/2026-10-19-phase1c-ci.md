# Knowledge bot phase 1c: CI build, append and publish implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, append to and publish a consumer's knowledge index from GitHub Actions: nightly full rebuild, append on issue and pull request close, Actions cache with artifact fallback, health reporting, and a self-test that runs on every push of the shared repository.

**Architecture:** All logic lives in `bot-scripts` as testable TypeScript CLIs (`index-status`, `append`, `validate-config`) over the existing readers, writer and raw store. Composite actions under `actions/` are thin shells around those CLIs plus the first-party `actions/cache`, `actions/upload-artifact` and `gh`. Reusable workflows under `.github/workflows/` check out the shared repository at their own commit (`github.job_workflow_sha`) so actions and scripts always match the workflow version. Consumers hold two thin caller workflows.

**Tech Stack:** TypeScript on Node 24 (type stripping), `node:sqlite` + `sqlite-vec`, GitHub Actions (composite actions, reusable workflows, `actions/cache` v6, `actions/upload-artifact` v7, `gh` CLI on the runner).

## Global Constraints

- Node floor `>=24`; sources are `.ts` run by type stripping, imports keep the `.ts` extension, `npm test` must exit 0 (strict `tsc` on `src`, lenient on `test`, then `node --test`).
- No new runtime dependencies. `bot-scripts` is installed in CI with `npm ci --ignore-scripts --omit=dev`.
- No network in unit tests: every HTTP call goes through an injectable `fetchImpl`.
- Actions are pinned by full SHA with a version comment (`actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`, `actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0`, `actions/cache@55cc8345863c7cc4c66a329aec7e433d2d1c52a9 # v6.1.0`, `actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2`, `actions/download-artifact@9000827ccba6bdab643e8b6fd33ac0654aef8333 # v8.0.2`). Only first-party `actions/*` actions and `gh`; no third-party actions.
- Every `run:` script reads untrusted values (inputs, event payload, config) from `env:`, never through `${{ }}` interpolation inside the script. `persist-credentials: false` on every checkout. Workflow token only, no new secret.
- YAML files start with `---` and the `on:` line carries `  # yamllint disable-line rule:truthy` (two spaces), as the pre-commit hook requires.
- Cache keys: `<slug>-index-v<format version>-<run id>` and `<slug>-raw-v<raw schema version>-<run id>`, restored by prefix; artifacts `<slug>-index` and `<slug>-raw`, 30 day retention.
- Rate limits measured on 2026-10-19: a first android fill is about 11 000 REST requests; a user token has 5000 per hour, the Actions `GITHUB_TOKEN` 1000 per hour; the client waits out a window (up to 61 minutes). The build job therefore saves the raw store even when the build fails, so the first fill converges over successive runs.
- Commits go on `main` in `auto-triage` (Timo's standing permission for the proof of concept); the android repository is only edited, never committed.
- Files under about 300 lines, functions under 50.

## Review Focus

1. An index file whose `meta` says another model or schema must be reported `unusable`, never served (Task 1 test `reports an index built with another model as unusable`).
2. Appending an item that already exists must leave exactly one copy, with its old chunks gone from `chunks`, `chunks_fts` and `vec_chunks` (Task 2 test `replaces an existing item and all of its chunks`).
3. Appending an issue that no longer qualifies (now a pull request, or a bot pull request) must remove it rather than fail (Task 4 test `removes an item the config no longer wants`).
4. A build that dies on a rate limit must still save the raw store so the next run continues (Task 10: the `publish raw` step runs `if: always()`; checked by reading the workflow, not by a unit test).
5. A `pull_request` close from a fork must not run with the fork's cache scope or a checkout of fork code (Task 13: the consumer uses `pull_request_target` with no checkout; checked by reading the workflow).

```ts
import { existsSync } from 'node:fs';
import { openDatabase, readMeta, FORMAT_VERSION, SCHEMA_VERSION } from '../store/db.ts';
import { RAW_SCHEMA_VERSION } from '../store/raw.ts';
import { modelKeyOf } from '../embed/embedder.ts';
import type { Config } from '../config/types.ts';

const DAY_MS = 24 * 60 * 60 * 1000;

export interface IndexStatus {
  found: boolean;
  usable: boolean;
  reason: string | null;
  status: 'fresh' | 'stale' | 'unusable' | 'missing';
  builtAt: string | null;
  ageDays: number | null;
  items: number;
  chunks: number;
  formatVersion: number;
  schemaVersion: number;
}

export interface IndexStatusInput { indexPath: string; config: Config; now?: Date; freshDays?: number }

const missing = (): IndexStatus => ({ found: false, usable: false, reason: 'no index file', status: 'missing', builtAt: null, ageDays: null, items: 0, chunks: 0, formatVersion: FORMAT_VERSION, schemaVersion: SCHEMA_VERSION });
const unusable = (reason: string): IndexStatus => ({ ...missing(), found: true, reason, status: 'unusable' });

/** The three versions a cache key or a consumer may need without opening an index. */
export function rawVersions(): { formatVersion: number; schemaVersion: number; rawSchemaVersion: number } {
  return { formatVersion: FORMAT_VERSION, schemaVersion: SCHEMA_VERSION, rawSchemaVersion: RAW_SCHEMA_VERSION };
}

/** What blocks serving an index with this config, or null. */
function blocker(meta: Record<string, string>, config: Config): string | null {
  if (meta.schema_version !== String(SCHEMA_VERSION)) return `schema ${meta.schema_version} != ${SCHEMA_VERSION}`;
  if (meta.format_version !== String(FORMAT_VERSION)) return `format ${meta.format_version} != ${FORMAT_VERSION}`;
  const wanted = modelKeyOf(config.embedding);
  if (meta.model_key !== wanted) return `model ${meta.model_key} != ${wanted}`;
  if (meta.dimensions !== String(config.embedding.dimensions)) return `dimensions ${meta.dimensions} != ${config.embedding.dimensions}`;
  return null;
}

/** Reads an index file's meta and says whether this config can serve it and how old it is. Never throws on a bad file. */
export function indexStatus({ indexPath, config, now = new Date(), freshDays = 2 }: IndexStatusInput): IndexStatus {
  if (!existsSync(indexPath)) return missing();
  let meta: Record<string, string>;
  try {
    const db = openDatabase(indexPath, { readOnly: true });
    try {
      meta = readMeta(db);
    } finally {
      db.close();
    }
  } catch (error) {
    return unusable(`cannot open: ${error instanceof Error ? error.message : String(error)}`);
  }
  const reason = blocker(meta, config);
  const builtAt = meta.built_at ?? null;
  const ageDays = builtAt ? (now.getTime() - Date.parse(builtAt)) / DAY_MS : null;
  const base = {
    found: true, builtAt, ageDays, items: Number(meta.item_count ?? 0), chunks: Number(meta.chunk_count ?? 0),
    formatVersion: Number(meta.format_version ?? FORMAT_VERSION), schemaVersion: Number(meta.schema_version ?? SCHEMA_VERSION),
  };
  if (reason) return { ...base, usable: false, reason, status: 'unusable' };
  return { ...base, usable: true, reason: null, status: ageDays !== null && ageDays < freshDays ? 'fresh' : 'stale' };
}
```

`src/store/upsert.ts`:

```ts
import type { DatabaseSync } from 'node:sqlite';
import { openDatabase, readMeta } from './db.ts';
import { chunkHash, statements, insertItem, insertChunk, type WriteStats } from './writer.ts';
import { quantizeInt8, toBlob } from './vectors.ts';
import type { Embedder } from '../embed/embedder.ts';
import type { IndexItem } from '../providers/types.ts';

export interface ItemRef { provider: string; origin: string; source: string; sourceId: string }

const FIND_ITEM = 'SELECT id FROM items WHERE provider = ? AND origin = ? AND source = ? AND source_id = ?';

/** Vectors of an item's current chunks by hash, then its rows removed: vectors first, chunks, item. */
function deleteItem(db: DatabaseSync, itemId: number | bigint): Map<string, Uint8Array> {
  const rows = db.prepare('SELECT c.hash, v.embedding FROM chunks c LEFT JOIN vec_chunks v ON v.chunk_id = c.id WHERE c.item_id = ?').all(itemId) as { hash: string; embedding: Uint8Array | null }[];
  const vectors = new Map<string, Uint8Array>();
  for (const row of rows) if (row.embedding) vectors.set(row.hash, row.embedding);
  db.prepare('DELETE FROM vec_chunks WHERE chunk_id IN (SELECT id FROM chunks WHERE item_id = ?)').run(itemId);
  db.prepare('DELETE FROM chunks WHERE item_id = ?').run(itemId);
  db.prepare('DELETE FROM items WHERE id = ?').run(itemId);
  return vectors;
}

/** Rebuilds the FTS index and the counts after rows changed. */
function finish(db: DatabaseSync): void {
  db.exec(`INSERT INTO chunks_fts(chunks_fts) VALUES('rebuild')`);
  const count = (sql: string) => String((db.prepare(sql).get() as { n: number }).n);
  const meta = db.prepare('INSERT OR REPLACE INTO meta (key, value) VALUES (?, ?)');
  meta.run('item_count', count('SELECT count(*) n FROM items'));
  meta.run('chunk_count', count('SELECT count(*) n FROM chunks'));
  meta.run('appended_at', new Date().toISOString());
}

export interface UpsertInput { indexPath: string; items: AsyncIterable<IndexItem>; embedder: Embedder; log?: (line: string) => void }

/** Replaces or adds items in an existing index in place, one transaction per item. */
export async function upsertItems({ indexPath, items, embedder, log = () => {} }: UpsertInput): Promise<WriteStats> {
  const db = openDatabase(indexPath);
  const stats: WriteStats = { items: 0, chunks: 0, embedded: 0, reused: 0 };
  try {
    const meta = readMeta(db);
    if (meta.model_key !== embedder.modelKey) throw new Error(`Index model ${meta.model_key} does not match ${embedder.modelKey}`);
    const stmt = statements(db);
    const find = db.prepare(FIND_ITEM);
    for await (const item of items) {
      const existing = find.get(item.provider, item.origin, item.source, item.sourceId) as { id: number | bigint } | undefined;
      const known = existing ? deleteItem(db, existing.id) : new Map<string, Uint8Array>();
      const chunks = item.chunks.filter((c) => c.text.trim());
      const texts = chunks.map((c) => c.text);
      const hashes = chunks.map(chunkHash);
      const toEmbed = chunks.map((_, i) => i).filter((i) => !known.has(hashes[i]));
      const vectors = toEmbed.length ? await embedder.embed(toEmbed.map((i) => texts[i])) : [];
      db.exec('BEGIN');
      try {
        const itemId = insertItem(stmt, item);
        chunks.forEach((chunk, i) => {
          const chunkId = insertChunk(stmt, itemId, chunk, hashes[i]);
          const reused = known.get(hashes[i]);
          if (reused) {
            stmt.vector.run(chunkId, reused);
            stats.reused += 1;
          } else {
            stmt.vector.run(chunkId, toBlob(quantizeInt8(vectors[toEmbed.indexOf(i)])));
            stats.embedded += 1;
          }
        });
        db.exec('COMMIT');
      } catch (error) {
        db.exec('ROLLBACK');
        throw error;
      }
      stats.items += 1;
      stats.chunks += chunks.length;
      log(`${existing ? 'replaced' : 'added'} ${item.source} ${item.origin}#${item.sourceId}: ${chunks.length} chunks`);
    }
    finish(db);
  } finally {
    db.close();
  }
  return stats;
}

/** Deletes one item with its chunks and vectors; true when it existed. */
export function removeItem({ indexPath, ref }: { indexPath: string; ref: ItemRef }): boolean {
  const db = openDatabase(indexPath);
  try {
    const existing = db.prepare(FIND_ITEM).get(ref.provider, ref.origin, ref.source, ref.sourceId) as { id: number | bigint } | undefined;
    if (!existing) return false;
    db.exec('BEGIN');
    deleteItem(db, existing.id);
    db.exec('COMMIT');
    finish(db);
    return true;
  } finally {
    db.close();
  }
}
```

export function parseItemRef(text: string): ItemRefText {
  const match = /^(issue|pull):(\d+)$/.exec(text.trim());

  const section = ref.kind === 'issue' ? repoConfig?.issues : repoConfig?.pulls;

  async function* one() { yield item!; }
  const stats = await upsertItems({ indexPath, items: one(), embedder, log });

### Task 10: Reusable workflow `build-index.yml`

**Files:**
- Create: `.github/workflows/build-index.yml`

**Interfaces:**
- `workflow_call` inputs: `slug` (string, required), `config` (string, default `.github/knowledge-bot.yaml`), `checkouts` (string, default `''`: newline-separated `owner/repo` list cloned shallowly from GitHub into `.knowledge-bot/checkouts/<owner>/<repo>` and passed as `--checkout owner/repo=<path>`; the consumer's own repository is always passed as `--self .` and `--checkout <repo>=.`), `timeout-minutes` (number, default 350), `tracking` (boolean, default true).
- Permissions required from the caller: `contents: read`, `actions: read`, `issues: write`.
- Steps: checkout consumer (`persist-credentials: false`); resolve the shared repository from `github.job_workflow_ref` and check it out at `github.job_workflow_sha` into `.knowledge-bot/auto-triage`; `setup-bot`; `restore-index` (previous index and raw store); clone extra checkouts; build with `--previous`, `--raw`, `--self .`; `publish-index` on success; `publish-index` with `publish-index: 'false'` when the build failed (`if: failure()`), so the raw store progress survives a rate-limit abort; status of the new index; `report-index-status`.
- Concurrency group `knowledge-index-<slug>`, `cancel-in-progress: false`, so a build and an append never write the cache at the same time.

- [ ] **Step 1: Write the workflow**

```yaml
---
name: Build knowledge index

on:  # yamllint disable-line rule:truthy
  workflow_call:
    inputs:
      slug:
        type: string
        required: true
      config:
        type: string
        default: .github/knowledge-bot.yaml
      checkouts:
        description: Newline-separated owner/repo list of extra repositories read from a checkout (docs).
        type: string
        default: ''
      timeout-minutes:
        type: number
        default: 350
      tracking:
        type: boolean
        default: true

permissions: {}

concurrency:
  group: knowledge-index-${{ inputs.slug }}
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    timeout-minutes: ${{ inputs.timeout-minutes }}
    permissions:
      contents: read
      actions: read
      issues: write
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - id: self
        env:
          JOB_WORKFLOW_REF: ${{ github.job_workflow_ref }}
        run: |
          set -euo pipefail
          echo "repo=${JOB_WORKFLOW_REF%%/.github/*}" >> "$GITHUB_OUTPUT"
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          repository: ${{ steps.self.outputs.repo }}
          ref: ${{ github.job_workflow_sha }}
          path: .knowledge-bot/auto-triage
          persist-credentials: false
      - uses: ./.knowledge-bot/auto-triage/actions/setup-bot
        with:
          config: ${{ inputs.config }}
      - id: previous
        uses: ./.knowledge-bot/auto-triage/actions/restore-index
        with:
          slug: ${{ inputs.slug }}
          config: ${{ inputs.config }}
        env:
          GH_TOKEN: ${{ github.token }}
      - id: checkouts
        env:
          CHECKOUTS: ${{ inputs.checkouts }}
          OWN_REPO: ${{ github.repository }}
        run: |
          set -euo pipefail
          args=(--self . --checkout "$OWN_REPO=.")
          while IFS= read -r repo; do
            repo="${repo//[[:space:]]/}"
            [ -z "$repo" ] && continue
            [[ "$repo" =~ ^[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+$ ]] || { echo "bad checkout $repo" >&2; exit 1; }
            dir=".knowledge-bot/checkouts/$repo"
            git clone --depth 1 --quiet "https://github.com/$repo.git" "$dir"
            args+=(--checkout "$repo=$dir")
          done <<< "$CHECKOUTS"
          printf '%s\n' "${args[@]}" > .knowledge-bot/checkout-args
      - id: build
        env:
          GITHUB_TOKEN: ${{ github.token }}
          CONFIG: ${{ inputs.config }}
          INDEX: ${{ steps.previous.outputs.index-path }}
          RAW: ${{ steps.previous.outputs.raw-path }}
          PREVIOUS_USABLE: ${{ steps.previous.outputs.usable }}
        run: |
          set -euo pipefail
          mapfile -t args < .knowledge-bot/checkout-args
          previous=()
          if [ "$PREVIOUS_USABLE" = "true" ]; then cp "$INDEX" "$INDEX.previous"; previous=(--previous "$INDEX.previous"); fi
          node "$BOT_SCRIPTS_DIR/src/cli/build.ts" --config "$CONFIG" --out "$INDEX" --raw "$RAW" \
            --model-cache "$KB_MODEL_CACHE" "${previous[@]}" "${args[@]}"
          rm -f "$INDEX.previous"
      - if: success()
        uses: ./.knowledge-bot/auto-triage/actions/publish-index
        with:
          slug: ${{ inputs.slug }}
          config: ${{ inputs.config }}
          index-path: ${{ steps.previous.outputs.index-path }}
          raw-path: ${{ steps.previous.outputs.raw-path }}
      - if: failure()
        uses: ./.knowledge-bot/auto-triage/actions/publish-index
        with:
          slug: ${{ inputs.slug }}
          config: ${{ inputs.config }}
          index-path: ${{ steps.previous.outputs.index-path }}
          raw-path: ${{ steps.previous.outputs.raw-path }}
          publish-index: 'false'
      - id: status
        if: always()
        env:
          CONFIG: ${{ inputs.config }}
          INDEX: ${{ steps.previous.outputs.index-path }}
        run: node "$BOT_SCRIPTS_DIR/src/cli/index-status.ts" --config "$CONFIG" --index "$INDEX"
      - if: always()
        uses: ./.knowledge-bot/auto-triage/actions/report-index-status
        with:
          slug: ${{ inputs.slug }}
          status: ${{ steps.status.outputs.status }}
          source: ${{ steps.build.outcome == 'success' && 'build' || steps.previous.outputs.source }}
          age-days: ${{ steps.status.outputs.age-days }}
          reason: ${{ steps.status.outputs.reason }}
          tracking: ${{ inputs.tracking }}
        env:
          GH_TOKEN: ${{ github.token }}
```

Notes: a failed build leaves the previous index file untouched (the writer renames only on success), so the `status` step after a failure reports the previous index. The `previous` restore keeps the earlier cache entry alive by re-saving it only when the build succeeds; eviction between failed runs is covered by the artifact fallback.

- [ ] **Step 2: Write the self-test workflow**

```yaml
---
name: Pipeline self-test

on:  # yamllint disable-line rule:truthy
  pull_request:
  push:
    branches: [main]

permissions: {}

jobs:
  config:
    uses: ./.github/workflows/selfcheck.yml
    permissions:
      contents: read
    with:
      config: examples/selfcheck/knowledge-bot.yaml
  build:
    uses: ./.github/workflows/build-index.yml
    permissions:
      contents: read
      actions: read
      issues: write
    with:
      slug: selfcheck
      config: examples/selfcheck/knowledge-bot.yaml
      timeout-minutes: 30
      tracking: false
  verify:
    needs: build
    runs-on: ubuntu-latest
    timeout-minutes: 15
    permissions:
      contents: read
      actions: read
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
      - uses: ./actions/setup-bot
        with:
          config: examples/selfcheck/knowledge-bot.yaml
      - id: index
        uses: ./actions/restore-index
        with:
          slug: selfcheck
          config: examples/selfcheck/knowledge-bot.yaml
        env:
          GH_TOKEN: ${{ github.token }}
      - env:
          STATUS: ${{ steps.index.outputs.status }}
          SOURCE: ${{ steps.index.outputs.source }}
          INDEX: ${{ steps.index.outputs.index-path }}
        run: |
          set -euo pipefail
          [ "$STATUS" = "fresh" ] || { echo "expected a fresh index, got $STATUS" >&2; exit 1; }
          [ "$SOURCE" = "cache" ] || [ "$SOURCE" = "artifact" ] || { echo "unexpected source $SOURCE" >&2; exit 1; }
          out="$(node "$BOT_SCRIPTS_DIR/src/cli/query.ts" --config examples/selfcheck/knowledge-bot.yaml --index "$INDEX" --model-cache "$KB_MODEL_CACHE" "raw source store for the benchmark")"
          echo "$out" | head -20
          echo "$out" | grep -q phase1b || { echo "query did not reach the plan docs" >&2; exit 1; }
```

Note: on a pull request the cache is scoped to the PR branch, so `build` saves and `verify` restores inside the same scope; on `main` both use the default scope. The restore in `verify` runs in a different job of the same run, which is why `publish-index` keys include the run id: the prefix restore finds the entry the build job just saved.
